# ADR-0001: UFO and designspace as the source format

## Context and Problem Statement

Offentlig Sans starts from Public Sans `develop` at commit `e40fcf567` (https://github.com/uswds/public-sans). Upstream keeps `.glyphs` files (Glyphs app format) as the source of truth and stores a derived UFO copy. A source format has to be chosen for this repository before any edit is made, because every later change builds on it.

## Considered Options

1. **Keep `.glyphs` files.** Keeps the 435 Glyphs metric keys and allows editing in the Glyphs app. Needs a proprietary editor for a clean round trip and ties the repository to glyphsLib behaviour at every build.
2. **UFO plus designspace, converted once from `.glyphs`.** Plain-text, diffable, supported by every font editor and by fontmake and fontc without a conversion step.
3. **`.glyphspackage`.** Diffable like UFO, but still tied to the Glyphs app.

## Decision Outcome

Option 2. The `.glyphs` files were patched with the three upstream fixes, renamed, converted once with glyphsLib 6.17.2 (`--minimal`), and the Regular master was generated by interpolating Thin and Black. The `.glyphs` files are not kept in the repository.

### Invariants & Negative Constraints

- `sources/*.designspace` and `sources/*.ufo` are the only source of truth for outlines, kerning, groups and OpenType features. Do not reintroduce `.glyphs` files or build from them.
- The Regular master (`wght` 400) is a regular master from now on. It is no longer derived from Thin and Black, so a change to Thin or Black does not reach Regular unless it is repeated there.
- Upstream fixes that are not yet merged upstream stay in these sources and are tracked in `ROADMAP.md`. Upstream changes are merged by hand as UFO edits.
- Vertical metrics live in the UFO `fontinfo.plist` files and are recorded in `ARCHITECTURE.md`.

### Negative Consequences

- **Glyphs metric keys are gone.** Verified worst case: the 435 `widthMetricsKey` and similar keys do not exist in the UFOs, so opening the sources in the Glyphs app no longer propagates sidebearings from base glyphs. Widths are explicit, so output does not change. Set aside: a lossless round trip to Glyphs.
- **Upstream merges are manual.** Verified worst case: an upstream `.glyphs` change cannot be applied with `git merge`. Set aside: a trivial upstream sync.
- **Regular interpolation rounding.** Verified worst case: static instances other than Thin, Regular and Black differ by at most 1 font unit (2000 per em) in some outline points and kerning values compared with interpolating Thin and Black directly, because intermediate weights now interpolate from the Regular master and rounding ties resolve differently. Advance widths differ by at most 1 unit in one weight (ExtraLight Italic). Set aside: bit-identical intermediate weights.
- **Build-path curve differences.** Verified worst case: building through gftools builder instead of fontmake directly from `.glyphs` changes the quadratic approximation of overlapping composites such as `aringacute` and `Aringacute` by under 1.5k square font units of area (below one unit of edge shift); renderings are identical at display sizes. Set aside: bit-identical outlines to a Glyphs-app build.
